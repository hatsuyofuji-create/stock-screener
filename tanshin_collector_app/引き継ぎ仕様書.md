# 決算短信 受注高トラッカー ― 引き継ぎ仕様書

このドキュメントは、開発の続きを別のClaude（Claudeプロジェクト）に引き継ぐための仕様書です。
新プロジェクトの「ナレッジ」にこのファイルを入れ、後述の `.py` ファイル一式を一緒にアップして
ください。それだけで、別のClaudeが現状を把握して続きを進められます。

---

## 0. これは何か（ゴール）

**証券コードを入れるだけで、決算短信PDFを自動収集し、各四半期の「受注高（単独Q）」・
売上高・受注残高を抽出して、時系列（横並び）で表示／CSV出力するWebアプリ（Streamlit）。**

- 利用者は個人投資家（プログラミングは非専門）。Windows PCで、バッチをダブルクリックして使う。
- いちばんの目的は **受注高（各Q単独・百万円）を正確に拾う** こと。
- 受注高は決算短信PDFの本文/補足情報にしか無い（J-Quantsの財務データには入っていない）。
  そのため **PDFを解析** する。会社ごとに「文章型（例: DMG森精機）」「表型（例: 岡本工作機械）」
  など様式がバラバラ。

## 1. 全体の流れ

```
証券コード入力
   ↓  IRBANK(irbank.net)から短信PDFを自動DL         … tanshin_collector.collect_tanshin()
   ↓  決算短信PDF/{コード}{会社名}/{期}_Q{n}.pdf に保存
   ↓  保存済みPDFを解析（AI or 正規表現）             … ir_scraper.extract_financials_from_pdf()
   ↓    ├ AI: PDFをそのままClaudeに渡す（本命）        … ai_pdf_extract.extract_financials_from_pdf_ai()
   ↓    ├ AI(旧): pdfplumberでテキスト化して渡す（保険）… ai_analyzer.extract_financials_with_ai()
   ↓    └ 正規表現（保険の保険）                       … ir_scraper 内の各種 _from_*()
   ↓  累計→各Q単独に換算                              … tanshin_collector._to_single()
   ↓  時系列（横）で表示 / CSV出力
```

**重要な数値の約束（全モジュール共通）**
- 単位はすべて **百万円**。
- **売上高・受注高＝累計値** で抽出し、呼び出し側で **各Q単独に換算**（単独Q2＝累計Q2−累計Q1 …）。
- **受注残高＝期末の時点値**（累計ではない。単独換算しない）。
- B/Bレシオ＝受注高÷売上高。

## 3. 今回のセッションで行った変更（差分と理由）

### 3-1. 受注高抽出を「PDF直読み」に強化（本丸）
- **問題**: 旧AI（`ai_analyzer`）は *pdfplumberでテキスト化したもの* をClaudeに渡すため、
  表型・文字化けPDFで受注高を取りこぼす（プロンプト自身が「表が読みにくい場合あり」と認めている）。
- **対応**: `ai_pdf_extract.py` を新設し、**PDFのバイト列をそのままClaudeに渡す**
  （`document`ブロック＝ネイティブPDF読取り。表も文章もスキャン画像も直接読む＝OCR不要）。
  返す形は `ai_analyzer.extract_financials_with_ai` と**完全同一**（sales/orders/backlog は累計・百万円）。
- **配線**: `ir_scraper.extract_financials_from_pdf()` のAI部を
  「まず `ai_pdf` → 失敗時 `ai_analyzer`(テキスト) → 正規表現」の順に。
  結果の `source` は `ai_pdf` / `ai` / `regex...` のいずれかになる（画面「抽出元」で確認可）。
- モデルは既定 `claude-opus-4-8`（`ANTHROPIC_MODEL` 環境変数で変更可）。

### 3-2. 保存先フォルダを固定＆会社名つきに
- `tanshin_collector.py` に `FIXED_OUT_ROOT` を新設（＝上記の実運用 `決算短信PDF` パスを直接指定）。
  そこが無ければ「銘柄フォルダが最も多い決算短信PDF」を自動選択、それも無ければ隣に作成。
- `_resolve_out_dir(code)`: 既存の「コードで始まるフォルダ（例 `6141DMG森精機`）」があれば再利用。
  無ければ `database.get_stock` の会社名を付けて `{コード}{会社名}`、名前不明なら `{コード}` のみ。

### 3-3. APIキーの自動発見
- `_get_api_key()`: `st.secrets` → 環境変数 → **上位フォルダの `.streamlit/secrets.toml` を直接パース**
  （`tomllib`）の順で探す。サブフォルダから起動しても親アプリのキーを拾える。
- ただし基本は「アプリ自身のフォルダの `.streamlit/secrets.toml`」を置くのが素直（利用者はこれで解決）。

### 3-4. 表示を「時系列・横」に
- 列＝各期Q（左→右で新しく）、行＝売上高/受注高/受注残高/B/Bレシオ。
- 数値列は `pd.to_numeric(errors="coerce")` で**必ず数値型**にそろえ、空セル（None）混在でも壊れないように。
- 編集グリッド（`st.data_editor`）は空セルが多いと**表示側でJSエラー**（lodash `isLength`）が出たため、
  **`st.dataframe`（読み取り専用）に変更**。編集はCSVをDLしてExcelで行う運用。
- 「抽出元・備考」は折りたたみに分離。受注高マイナス／AI未使用時は警告を表示。

### 3-5. 起動バッチの堅牢化
- `run_app.bat` / `setup.bat` は Python を `.venv → py → python → よくある導入先` の順で自動検出。
  エラーメッセージはASCIIのみ（日本語＋括弧が原因でバッチが誤実行される事故を回避）。
- Windowsのzip展開で日本語ファイル名が文字化けするため、配布フォルダ／ファイル名は英語にした。

## 5. 未解決・次にやること（TODO）

### 5-1. 受注高が None になる銘柄の切り分け（最優先）
- 例: **6231（木村工機）** で受注高が全期 None。原因は次のどちらか未確定：
  1. その会社が**そもそも受注高を開示していない**（普通にある）
  2. **AI抽出が効いていない/失敗**（`source` が `ai_pdf` でない、キー未読込み 等）
- **確認手順**:
  - 画面「抽出元・備考」を開き、`抽出元` が **`ai_pdf`** か確認。
  - **受注高を確実に開示している銘柄で検証**：**6141（DMG森精機）** を AI ON で解析し、
    受注高が数字で入るか見る。入れば「6231は開示していないだけ」。
    入らなければ AI経路の不具合として調査。
- （メモ）6141は最初の検証画像で受注高（連結受注額）を明示している会社。テストの基準に最適。

### 5-2. 収集の「未取得（スキップ）」を減らす
- 6141収集時に「取得5件／スキップ13件」で、多くの四半期が欠けた。
- 画面下「⚠️ 警告・スキップ N件」を**開くとスキップ理由**が出る（`collect_tanshin` の `errors`）。
  例:「PDFリンクが見つからない」「取得失敗」。
- IRBANKのページ構造・リンク形式（`/{code}/(1401\d{12,16})`、詳細ページの
  `f.irbank.net/pdf/...`）に依存。理由を見てから収集ロジック（`list_tanshin`/`detail_pdf_url`）を調整する。
- 開発環境からIRBANKに接続できないことがある（プロキシ遮断）。実PDF/実HTMLの共有があると診断が速い。

### 5-3. セキュリティ
- スクショにAPIキーが写ったことがある。**AnthropicとJ-Quantsのキーは再発行（Revoke→新規）推奨**。
  新キーを `.streamlit/secrets.toml` に上書きすれば動作継続。

### 5-4. 改善余地（任意）

## 6. 動かし方（セットアップ）

1. `業績予想アプリ` フォルダ（`.py` 一式がある場所）で `setup.bat` をダブルクリック（初回のみ・ライブラリ導入）。
2. `.streamlit/secrets.toml` に `[anthropic] api_key = "sk-ant-..."` を記入（AI抽出に必須）。
3. `run_app.bat` をダブルクリック → ブラウザで開く（http://localhost:8502）。
4. コード入力→「決算短信を収集」→「AIで抽出する」ON→「保存済みPDFを解析」。
5. 「抽出元」が `ai_pdf` で、受注高がプラスの妥当な値なら成功。CSVをDL→必要ならExcelで補正。

- 実行環境: Windows / Python 3.14（`py`ランチャ検出でOK）。
- 主要ライブラリ: streamlit, requests, pandas, beautifulsoup4, pdfplumber, anthropic。
