# CLAUDE.md — pair-analysis 設計メモ

「先行→後続（リード・ラグ）」の連動を測る **検証・表示ツール**。
売買判断・発注ロジックは持たない（jp-sector-flow と同じ方針）。

## 全体像

```
             データ取得            計算(純Python)            表示 / 出力
 analyze.py → PriceProvider → analysis.analyze_pair → CLI表示 / JSON
 scan.py   → (yahoo/synth)                          → 総当たりランキング
 app.py    →                                        → Streamlit UI
```

- コア計算（`src/analysis.py`）は **pandas / numpy に依存しない純Python**。
  ネット接続なしで単体テストできる。UI・データ取得から独立。
- データ取得は必ず `PriceProvider` 経由（`get_provider()`）。yfinance を
  analyze/scan/app に直書きしない（jp-sector-flow の DataProvider と同じ契約思想）。

## 計算の定義（analysis.analyze_pair）

- 入力: 先行・後続それぞれの (dates, closes)。共通日付で `align` してから測る。
- **ベータ** = 後続リターン(t+lag) を 先行リターン(t) に回帰した傾き。
  「先行1%→後続の動き」。しきい値に依らず全営業日で測る。
- **相関 r** = 同じ (先行, 後続 lag後) の組のピアソン相関。太さ判定（±0.15/0.25）に使う。
- **lag** = 後続を未来にずらす営業日数。米欧→日本は 1（翌営業日に伝わる）。
  同時間帯（日本/韓国/台湾）の「連れ高確認」は 0 も可（`universe.default_lag`）。
- **イベント集計** = 先行が ±しきい値 を超えた急変日だけを抽出。
  - 上げ: 先行>+thr の翌 lag 日で後続>0 を「追随」。追随率と平均リターン。
  - 下げ: 先行<-thr の翌 lag 日で後続<0 を「追随」（守りのアラート検証）。
- **散布図** = 急変日ごとの (先行%, 後続%, 追随フラグ)。
- **重ね描き** = 共通開始=100 に正規化した両系列。

## スキャン（scan.py）の「筋通し」

相関の強さだけで並べると偶然の相関も上位に来る。`src/econ.THEMES` に属する同一テーマの
ペアは `THEME_BONUS`(=1.5) 倍で加点し、「銅→住友鉱山」等 意味の通るペアを上げる。
これは説明可能性のヒントで因果の保証ではない。

## データ提供元

- `synthetic`（既定）: シンボルから決めた乱数シードの擬似価格。鍵・ネット不要で
  テストとオフライン確認に使う。乱数なので相関はほぼ0（配線確認用）。
- `yahoo`: yfinance の調整後終値。取引所をまたぐので日付は各シンボルの営業日で返し、
  突き合わせは `analysis.align` に任せる。プロセス内 dict で簡易キャッシュ。

## 既知の TODO / 限界

- 祝日・半日立会の扱いは営業日ベースで簡略化（共通日付の積集合で吸収）。
- 為替の影響（米国株×日本株）は未調整。円建て/現地通貨の差は残る。
- lag は市場ベースの一律既定。個別に最適 lag を探索する機能は未実装。
- 700万通りの総当たりは取得がボトルネック。大ユニバースは分割・キャッシュ前提。

## ルール

- 秘密情報（APIキー等）はコード直書き禁止（yfinance は鍵不要だが方針は踏襲）。
- データ取得は必ず PriceProvider 経由。
- 表示・検証専用の方針を変えない（自動発注は追加しない）。
