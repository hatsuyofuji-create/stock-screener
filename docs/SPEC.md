## 0. プロジェクトの目的

個人投資家が、上原メソッドに基づいて「**価値が拡大する優良企業を、割安な価格で買う**」判断を、
再現性のあるルールとして半自動で行えるようにする意思決定支援アプリを作る。

中核となる判断は次の2軸：

- **価値（質）の軸**：財務健全性・収益性・成長性・競争優位性（Fスコア、ROA/ROIC 等）
- **価格（割安さ）の軸**：適正株価に対する現在株価の乖離（安全域％）

最終アウトプットは「**低PBR × Fスコア7以上**」を中心とした銘柄マトリクスと、
適正株価に基づく安全域の試算、そしてポートフォリオの利確・損切り管理。

> **重要（免責）**：本アプリは投資助言ツールではなく、投資判断は利用者自身の責任で行うもの。
> UI 上にもその旨を明記すること。外部データの取得は各サービスの利用規約を遵守すること。

## 1. 全体アーキテクチャ（3層）

```
① データ層        EDINET・TDnet 自動取得 / 市場データ / ユーザー予想Excel・定性メモ
        │
        ▼
② 分析エンジン層   財務指標＋Fスコア算出 / スクリーニング（閾値・魔法の公式）/ 適正株価・安全域算出
        │
        ▼
③ 出力・管理層     銘柄マトリクス（低PBR×Fスコア）/ ポートフォリオ管理 / 利確・損切アラート
```

処理は常に「集める → 採点・評価する → 判断する」の一方向パイプライン。

## 2. 技術スタック（推奨）

| 領域 | 推奨 | 理由 |
|---|---|---|
| バックエンド | Python + FastAPI | EDINET/XBRL のパースと pandas による財務計算が容易 |
| Excel パース | openpyxl（サーバ側） | ユーザーの予想Excel取り込み |
| DB | SQLite（初期）→ PostgreSQL | 単一ユーザーで始め、拡張時に移行 |
| フロントエンド | React + TypeScript + Tailwind | マトリクス散布図・ダッシュボード |
| チャート | Recharts または D3 | 散布図・複数年トレンド |
| テスト | pytest（計算ロジック）/ Vitest（UI） | 計算の正しさをユニットテストで担保 |

> 計算ロジック（Fスコア・適正株価・スクリーニング）は必ずバックエンドに置き、
> フロントは表示に徹する。計算の正しさはユニットテストで検証する（後述の受け入れ基準参照）。

## 3. データモデル

指標は「**企業 × 決算期 × 指標**」の3次元で持つ。トレンド（前年比改善など）を扱うため、
必ず複数期（最低3期）を保持すること。

```
Company
  - code            (証券コード, PK)
  - name
  - sector          (業種)
  - market_cap      (時価総額)
  - growth_type     (安定成長 / シクリカル成長 / シクリカル / 業績低迷 / 新領域開拓)
  - moat_tags       (任意: スイッチングコスト / コスト競争力 / ブランド / ネットワーク効果 / 特許規制)
  - qualitative_note(定性メモ。ユーザーExcelの「前提」欄から取り込み)

FinancialStatement            (実績。EDINET/TDnet 由来)
  - company_code (FK)
  - fiscal_period               (決算期, 例 2025-03)
  - source                      (edinet / tdnet)
  - 売上高, 売上原価, 売上総利益, 営業利益, 経常利益, 純利益
  - 営業CF, 投資CF, 財務CF
  - 総資産, 自己資本, 流動資産, 流動負債, 有利子負債, 現預金, 短期有価証券
  - 棚卸資産, 売上債権, 仕入債務
  - 資本金, 発行済株式数
  - 配当金総額 / DPS

Forecast                      (予想。四季報 / ユーザーExcel / コンセンサス)
  - company_code (FK)
  - fiscal_period
  - source                      (user_excel / shikiho / consensus)
  - scenario                    (base / negative)
  - 予想売上高, 予想営業利益(or営業利益率), 予想純利益, 予想EPS, 予想BPS, 予想DPS
  - one_time_items              (減損など一時損益。negative シナリオ用)

Holding                       (保有銘柄)
  - company_code (FK)
  - buy_price, shares, buy_date
  - confidence                  (自信度 1-5)
  - thesis                      (投資アイデアのメモ)
```

派生指標（ROE, ROA, Fスコア, 適正株価, 安全域 等）は計算で求め、必要ならキャッシュする。

## 4. 機能仕様

### 4.1 財務指標計算エンジン（3章）

`FinancialStatement` から次を算出する。単年ではなく各期で計算し、前年比の増減も返すこと。

| 指標 | 計算式 |
|---|---|
| 粗利率 | 売上総利益 ÷ 売上高 |
| 営業利益率 | 営業利益 ÷ 売上高 |
| ROE | 純利益 ÷ 自己資本 |
| ROA | 経常利益 ÷ 総資産 |
| ROIC | 営業利益 ×（1 − 実効税率）÷（有利子負債 ＋ 自己資本）※実効税率デフォルト 0.30〜0.35 |
| 流動比率 | 流動資産 ÷ 流動負債 |
| 自己資本比率 | 自己資本 ÷ 総資産 |
| 純有利子負債 | 有利子負債 −（現預金 ＋ 短期有価証券） ※マイナス＝ネットキャッシュ |
| グロスD/E | 有利子負債 ÷ 自己資本 |
| ネットD/E | 純有利子負債 ÷ 自己資本 |
| 総資産回転率 | 売上高 ÷ 総資産 |
| CCC | 棚卸資産回転日数 ＋ 売上債権回転日数 − 仕入債務回転日数（回転日数 = 1 ÷ 回転率 × 365） |
| ROEデュポン分解 | 純利益率 × 総資産回転率 × 財務レバレッジ（＝収益性 × 効率性 × 安全性） |

- 収益性の主指標は **ROA / ROIC**（ROE はレバレッジで水増しされるため）。ROE はデュポン分解の内訳を必ず併記。
- 各指標に「前年比 改善／悪化」フラグを持たせる（Fスコアとトレンド表示で再利用）。

### 4.2 Fスコア計算エンジン（7章・ツール⑦）

9項目を Yes=1 / No=0 で採点し合計（0〜9）。**7以上＝財務健全、3以下＝不健全**。
比較は「最新期」対「前期」。実績版と予想版の2モードを持つ（予想版がより有効）。

```
収益性
  1. 純利益 > 0                                → 1
  2. 営業CF > 0                                → 1
  3. ROA(最新期) > ROA(前期)                    → 1  (改善)
  4. 営業CF > 純利益                            → 1  (利益の質)
  5. 営業利益率(最新期) > 営業利益率(前期)        → 1  (改善)
安全性
  6. 有利子負債÷総資産(最新期) < 前期            → 1  (減少)
  7. 流動比率(最新期) > 前期                     → 1  (改善)
  8. 資本金(最新期) <= 資本金(前期)              → 1  (増資していない)
生産性
  9. 総資産回転率(最新期) > 前期                 → 1  (改善)

Fスコア = 上記の合計
```

- **実績版**：EDINET/TDnet の確定値を使用。
- **予想版**：最新期の値をユーザー予想（`Forecast`）に差し替えて算出。← ユーザーExcelアップロードと直結する目玉機能。
- 低PBR ユニバースに対して有効性が高い（マトリクスと組み合わせて使う）。

### 4.3 適正株価・安全域エンジン（4〜6章・ツール⑤）

**マルチプル法**で適正株価を出す。

```
適正株価(PER基準)       = 予想EPS × 妥当PER
適正株価(PBR基準)       = 予想BPS × 妥当PBR
適正株価(配当利回り基準) = 予想DPS ÷ 妥当配当利回り

安全域％ = (適正株価 − 現在株価) ÷ 適正株価
```

- **妥当倍率（＝本質的価値の閾値）**：デフォルトは「対象企業の過去平均」または「同業他社の中央値」を自動提案。ユーザーが手動で上書き可能。
- 割安の理由が **構造的**なら妥当倍率を過去平均から割り引く、**一時的**なら過去平均に回帰する前提で置く（UI で選択）。
- **どの指標を主に使うか**は景気局面で切り替える（4.4 参照）。

**シナリオ（レンジ）とリスクリワード**：Park24 モデル⑤の2シナリオ構造を踏襲する。

```
アップサイド％  = (base シナリオの適正株価  − 現在株価) ÷ 現在株価
ダウンサイド％  = (negative シナリオの適正株価 − 現在株価) ÷ 現在株価
リスクリワード比 = アップサイド％ ÷ |ダウンサイド％|
```

「損小利大か？」をリスクリワード比で色分け表示すること。

#### 業績予想モデル（Park24 型シナリオ計算・STEP1）

ユーザーが売上高・営業利益率・配当性向・一時損益を入力すると、下流が芋づる式に決まる。

```
営業利益 = 売上高 × 営業利益率
純利益   = 営業利益 × (1 − 実効税率) − 一時損益(減損など)    # Park24: 実効税率≈0.35
EPS      = 純利益 ÷ 発行済株式数                             # 株式数が無い場合は基準期からの比例スケール
DPS      = EPS × 配当性向        (または直接入力)
BPS      = 前期BPS + EPS − DPS
ROE      = EPS ÷ 平均BPS(前期, 当期)
```

- base / negative の2シナリオを並列に持つ（negative は `一時損益` に減損等を入れる）。
- この計算結果（予想EPS/BPS/DPS）が 4.3 の適正株価と 4.2 の予想Fスコアの入力になる。

### 4.4 景気局面セレクター（6章）

現在の景気局面をユーザーが選択（将来は景気ウォッチャー調査等から自動推定）。局面に応じて
適正株価計算の**主指標を自動切替**し、各指標の信頼度を表示する。ルールテーブルとして持つ：

| 景気局面 | 主指標 |
|---|---|
| 底・底からの回復 | 低PSR・低PBR・ネットキャッシュ÷時価総額 |
| 回復の初期 | 高い増益率 |
| 順調な拡大 | 低PER |
| 拡大の後期 | 低PER・高リビジョン |
| 拡大の最終局面 | 高ROE・低EV/EBITDA |
| 後退の初期 | 高配当利回り・低EV/EBITDA |
| 後退の中期 | 低PBR・高自己資本比率 |
| 後退の後期 | 高ROE・高自己資本比率・ネットキャッシュ÷時価総額 |

- **シクリカル銘柄フラグ**が立っている企業は PER の高低を反転解釈（底＝高PERが買い、ピーク＝低PERが売り）し、PBR・ネットキャッシュ÷時価総額を前面に出す。

### 4.5 スクリーニングエンジン（7〜8章）

2モードを提供。ヒット件数をリアルタイム表示し、設定を保存できること。

**モードA：閾値フィルター**（各条件は可変・ON/OFF可）
```
配当利回り ≥ X
自己資本比率 ≥ Y
純有利子負債 < 0            (ネットキャッシュ)
FCF (= 営業CF + 投資CF) > 0
ROE ≥ 15%                  (厳しめ。緩和可)
時価総額 ≤ 1000億円         (小型株)
株価3年変化率 < 0          (逆張り。任意)
Fスコア ≥ 7
```

**モードB：グリーンブラットの魔法の公式（ランキング）**
```
1. 全銘柄を ROIC の高い順に順位付け（rank_roic）
2. 全銘柄を PBR の低い順に順位付け（rank_pbr）
3. 合成ランク = rank_roic + rank_pbr
4. 合成ランクの昇順で上位 N 社（デフォルト30）を投資対象とする
```

選定基準の有効性序列（配当利回り ＞ PBR ＞＞ PER）をスコア重み付けに反映してよい。

### 4.6 予想Excelアップロード & マッピング（ユーザー要件）

ユーザーの予想Excel（例：Park24 型の年次トップダウン、セーレン型の四半期ボトムアップ＋受注）は
**様式がバラバラ**なので、固定テンプレートを強制しない。取り込みアダプター（マッピング層）を実装する。

- アップロード後、シートをプレビュー表示。
- 「この行/セル ＝ 予想EPS・予想営業利益・売上高・DPS・BPS…」をユーザーがマッピング（`EPS` などの見出しは自動検出を試みる）。
- 最終的に `Forecast` に必要な少数の出力（**予想EPS・予想BPS・予想DPS ＋ 売上・営業利益・ROE**）だけを抽出する。
- Excel 内の「前提」欄などの自由記述テキストは `qualitative_note` として取り込み、銘柄ページの定量指標の隣に表示する（定性情報はユーザーのExcelを正とする）。
- マッピング設定は銘柄・様式ごとに保存し、次回以降は再利用する。

### 4.7 銘柄マトリクス（1章・7章・出力層の顔）

- 散布図：**横軸＝PBR（左が割安）、縦軸＝Fスコア（上が健全）**。
- 4象限を色分け：
  - 左上（低PBR × 高Fスコア）＝**本命ゾーン**（買い候補）
  - 左下（低PBR × 低Fスコア）＝**バリュートラップ警告**（赤）
  - 右上（高PBR × 高Fスコア）＝健全だが割高
  - 右下＝対象外
- 各点をクリックすると銘柄詳細（財務トレンド、Fスコア内訳、適正株価・安全域、定性メモ）へ。
- 高ROE × 低PBR の点は追加ハイライト（4章の「ROEが高いのにPBRが低い企業を探す」）。

### 4.8 ポートフォリオ管理・アラート（12章）

判断基準は常に**適正株価**。購入価格や含み益に判断を惑わされない設計にする。

- **利確アラート**：現在株価 ≥ 適正株価 に到達 → 成長タイプ別の利確ルールを適用して通知。
  - 成長企業：源泉が崩れない限り保有。割高すぎたらポジション調整。
  - シクリカル：景気ピーク or 過去平均バリュエーション到達で売却。
  - 業績苦戦（構造改革）：株価が「回復後利益 × 市場平均PER」到達で売却。
- **損切りアラート**：①想定シナリオ崩壊、②バリュートラップ判定（低PBR×低Fスコアが継続）、
  ③①②が無くても **2年以上含み損** が継続、のいずれか。
- **ポジションサイズ提案**：`自信度 × アップサイド％` に応じて推奨保有比率を提示。
- **分散チェック**：保有 5〜10 銘柄、業種偏りを可視化。金利上昇・災害などのシナリオでの影響を試算。
- **「今この株を非保有と仮定」再評価ボタン**：保有効果（行動バイアス）を外して買い直すか判断させる。

### 4.9 データ取得層（9章・自動取得の要件）

データは「①自動取得する数値」「②アップロードで賄う予想」「③人が読む定性」の3層に分ける。

| データ源 | 中身 | 自動取得 | 用途 |
|---|---|---|---|
| EDINET API | 有価証券報告書（XBRL） | ◎ 公式API | 財務三表 → 財務指標・Fスコア・スクリーニング |
| TDnet／適時開示 | 決算短信（業績・配当・予想） | ○ | 財務・DPS・カタリスト検知 |
| 市場データAPI | 株価・時価総額・PER/PBR/利回り | ○ | マトリクス・安全域 |
| ユーザーExcel | 予想EPS/営業利益 等 | 手動アップロード | STEP1 業績予想・予想Fスコア |
| 会社四季報 / 各種ツール | 加工済み指標・予想 | △ 規約要確認 | 補助のみ |

- 数値の主エンジンは **EDINET ＋ TDnet**（規約上クリーン）。バフェットコード・四季報・ニュースは規約を確認し補助にとどめる。
- 決算短信は「表紙（業績予想・配当）／経営成績の概況／財務諸表／セグメント別情報」の4項目を取得対象とする。

## 5. 実装フェーズ（この順に Claude Code へ指示する）

各フェーズはユニットテスト付きで完結させ、動作確認してから次へ進む。

- **Phase 0 — 雛形とデータモデル**：リポジトリ構成、DB スキーマ（第3章）、サンプル銘柄1社を手入力できる最小構成。
- **Phase 1 — 財務指標 ＋ Fスコアエンジン（コア）**：4.1 と 4.2 を実装。手入力／CSV で検証。**ここが心臓部**。
- **Phase 2 — 適正株価・安全域 ＋ Park24型シナリオ計算**：4.3 を実装。base/negative の2シナリオとリスクリワード。
- **Phase 3 — 予想Excelアップロード ＆ マッピング**：4.6 を実装。予想Fスコア・予想適正株価に接続。
- **Phase 4 — スクリーニング ＋ 銘柄マトリクス**：4.5 と 4.7。二刀流スクリーニングと散布図UI。
- **Phase 5 — データ自動取得**：4.9。EDINET/TDnet からの取り込みで手入力を置き換える。
- **Phase 6 — ポートフォリオ管理 ＋ アラート**：4.8 と 4.4（景気局面）。全機能を管理・通知として統合。

## 6. 受け入れ基準（テスト）

- **Fスコア**：ツール⑦の既知サンプル（実績版・予想版）と同じ入力で、同じ合計点になること。
  特に項目8（増資判定＝資本金の前期比）と項目4（営業CF > 純利益）の境界値をテストする。
- **Park24 モデル**：⑤と同じ入力（売上・営業利益率・配当性向・減損）で、
  EPS・BPS・ROE・base/negative の適正株価が一致すること。
- **安全域**：`(適正株価 − 現在株価) ÷ 適正株価` が手計算と一致。負値（割高）も正しく扱う。
- **スクリーニング（魔法の公式）**：小さなダミー銘柄集合で合成ランク上位が手計算と一致。
- **Excel取り込み**：様式の異なる2ファイル（年次型・四半期型）から、予想EPS/BPS/DPS を正しく抽出。

## 7. 用語・定数

- 実効税率（デフォルト）：0.30〜0.35（Park24 モデルは純利益 = 営業利益 × 0.65 を採用）
- Fスコア判定：7以上＝健全 / 3以下＝不健全
- 保有銘柄数の目安：5〜10
- 魔法の公式の採用社数（デフォルト）：30
- 損切りの時間基準：含み損が2年以上継続
